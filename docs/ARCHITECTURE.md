# Architecture and design decisions

## Data flow

```
homepub.config.json          (single source of truth, committed)
        |
        +-- plan.js ---------> in-memory files: frpc.toml, nginx/{bootstrap,sites}/*.conf,
        |                      acme.sh, install.sh, frps snippets, ports.md
        |                      ports assigned here (stable via ports.json)
        v
      out/  -----------------> copied to home server (client/) and public server (server/)
        |
        +-- doctor.js --------> TCP / DNS / HTTPS checks (read-only, no writes)
```

## Decisions

### 1. Generate, never mutate

Editing live config is where tools become dangerous: partial writes, unknown prior state, no rollback. homepub only writes files into `out/`. The install scripts back up every target file, run `nginx -t`, reload, and roll back automatically on failure.

### 2. Two-phase install (HTTP bootstrap -> ACME -> HTTPS)

A 443 server block cannot be tested before its certificate exists: `nginx -t` fails with "cannot load certificate", and the ACME webroot only exists in the not-yet-loaded config. So the install script:

1. installs an HTTP-only bootstrap per host (ACME challenge + 503),
2. `nginx -t` + reload,
3. runs the generated `acme.sh` (only if a certificate is missing),
4. installs the full HTTPS sites,
5. `nginx -t` + reload.

Any failure in step 2 or 4 triggers `rollback()`: remove added files, restore modified ones from the backup dir, re-test and reload.

### 3. Port ledger lives outside `out/`

`out/` is disposable. If tunnel port assignment lived there, deleting it would reshuffle ports and break DNS/firewall rules. The ledger is `paths.ledger` (default `./ports.json`) and is meant to be committed. `assignPorts()` keeps existing entries and only allocates for new services.

### 4. TCP tunnel + nginx TLS, not frp's `type = "http"`

With a TCP tunnel, certificates and TLS policy exist in one place (nginx), the public server is the only listener on 443, frps only sees encrypted bytes on loopback-bound ports, and WebSocket/HTTP2 work because nginx handles them.

### 5. `proxyBindAddr = "127.0.0.1"` must be a top-level key

TOML assigns keys after a `[table]` header to that table. The generator emits the key with an explicit warning to put it before the first table, and ships `frps.toml.example` as a safer alternative. Without it, tunnel ports bind to `bindAddr` (usually 0.0.0.0) and bypass TLS.

### 6. Stale file cleanup

Generated files carry a `# generated by homepub` header. `findObsolete()` only considers such files under `client/` and `server/`, so `--prune` can never delete a hand-written config. On the server, `install.sh` keeps `.homepub-managed` and removes vhosts of services no longer in the plan.

### 7. Doctor validates certificates

`checkHttps()` runs two probes: one with `rejectUnauthorized: true` (decides pass/fail) and one permissive (reads expiry/issuer). Expired or self-signed certificates are reported as failures instead of a false "all checks passed".

## Modules

| file | responsibility |
| --- | --- |
| `src/config.js` | parse + validate JSON, defaults, unknown-key warnings, path whitelist |
| `src/plan.js` | port assignment, assemble every output file |
| `src/render.js` | pure string builders (frpc TOML, nginx, shell scripts, ledger) |
| `src/apply.js` | diff against disk, write changed files, obsolete detection, chmod |
| `src/doctor.js` | TCP / DNS / HTTPS + certificate validation |
| `src/cli.js` | argument parsing, commands, table/JSON output |

## Testing

- `node --test "test/**/*.test.js"` — 33 unit tests: config validation, port stability, deterministic rendering, idempotent apply, obsolete/prune, doctor aggregation.
- `bash scripts/e2e-install.sh [out]` — fake nginx/acme.sh/systemctl: proves the two-phase install, rollback on `nginx -t` failure, and the placeholder-token abort.
